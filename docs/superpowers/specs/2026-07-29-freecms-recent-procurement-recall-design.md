# FreeCMS 近 30 天采购公告召回设计

日期：2026-07-29

## 1. 背景

中央政府采购网 `https://www.zycg.gov.cn/` 使用 FreeCMS。现有发现流程已经支持
站内关键词搜索、栏目发现和正文抓取，但 FreeCMS 的关键词接口主要按标题召回，
只出现在正文中的关键词仍可能漏检。

本次优化聚焦中央政府采购网最近 30 天的采购公告，通过关键词标题搜索和近期
公告列表两个通道补充候选，再抓取正文确认关键词，从而在可控预算内提高召回率。

## 2. 目标与范围

### 2.1 目标

- 对最近 30 天的采购公告尽量减少漏检。
- 标题或列表文本用于候选召回，正文用于确认强命中。
- 正文未命中但标题或列表文本命中的候选仍以弱命中返回。
- FreeCMS 可使用高于通用站点的时间和页面预算。
- 任一发现通道失败时，其他通道仍能继续工作并返回已有结果。

### 2.2 范围内

- 增强 FreeCMS 适配器和对应 Provider。
- 使用 `searchAll.do` 按关键词召回标题候选。
- 使用 `selectInfoMore.do` 按时间遍历采购公告主列表。
- 规范化、合并和去重两个通道的候选。
- 抓取候选正文并标注强弱命中。
- 增加 FreeCMS 专用预算、停止原因和诊断统计。
- 对结果 API 和现有前端做向后兼容的最小扩展。

### 2.3 范围外

- 不修改云南 CMS 或通用站点的默认发现行为。
- 不扫描采购公告主列表以外的所有历史栏目。
- 不承诺覆盖 30 天以前的历史公告。
- 不建设持久化全站索引或后台定时全量同步。
- 不绕过登录墙、验证码或访问控制。

## 3. 总体方案

采用 FreeCMS“双通道召回 + 强弱命中”：

1. `searchAll.do` 根据关键词召回标题相关的候选。
2. `selectInfoMore.do` 从采购公告主列表按时间倒序召回最近 30 天的候选。
3. 规范化 URL 后合并去重，并保留候选的全部来源证据。
4. 按候选分数抓取正文。
5. 正文包含关键词时标记为强命中。
6. 正文未命中，但标题或列表文本包含关键词时标记为弱命中。
7. 标题、列表和正文均不包含关键词的候选不返回。

该行为是 FreeCMS 近期采购公告模式的受控扩展。其他站点仍遵循现有“正文实际
命中才返回”的规则。

## 4. 召回通道

### 4.1 关键词标题搜索

`searchAll.do` 沿用现有会话预热和请求协议：

- 使用 `title`、`currPage` 和 `pageSize` 参数。
- 每个关键词默认最多翻 10 页，页数上限可配置。
- 响应带可靠日期且结果已早于 30 天窗口时，可提前停止后续翻页。
- 响应缺少日期时，不使用日期提前停止，只受页数和时间预算限制。
- 已知日期早于窗口的候选不进入近期结果。
- 日期未知的候选允许进入正文确认队列，以避免因接口字段缺失而漏检，并在诊断
  中计入 `unknownDateCandidates`。

### 4.2 近期采购公告列表

`selectInfoMore.do` 使用站点真实参数：

- `siteId`
- 采购公告 `channel`
- 当前站点使用的 `noticeType`
- 当前站点使用的 `implementWay`
- `currPage`
- `pageSize`
- 空 `title`

列表按时间倒序翻页，每页默认 15 条。满足下列任一条件即停止：

1. 当前页首次出现 `addtimeStr` 早于“当前日期减 30 天”的记录；该记录及其后
   更旧的记录不进入候选。
2. 达到默认 80 页的 FreeCMS 列表上限。
3. 共享时间预算耗尽。
4. 接口返回空页、业务失败或不可解析结构。

日期边界使用运行服务所在时区的自然日，截止日当天的公告仍在窗口内。只有在
接口结果保持时间倒序时才使用“遇到旧记录即停止”；若检测到日期乱序，则继续
翻页至页数或时间上限，并按单条日期过滤。

## 5. 候选合并与排序

- URL 经现有规范化逻辑处理后去重。
- 同一 URL 同时来自两个通道时只抓取一次，但保留全部来源和最高召回分。
- `searchAll.do` 的标题关键词命中具有较高初始分。
- `selectInfoMore.do` 仅因位于 30 天窗口而进入的候选具有中等初始分。
- 强命中排在弱命中之前。
- 同一强度内优先按发布日期从新到旧，再按候选分数从高到低。
- 日期未知的结果排在同强度、已知日期结果之后。

## 6. 强弱命中

### 6.1 强命中

成功抓取目标页面后，正文可见文本包含关键词。正文提取和匹配沿用现有
`match_body_*` 语义，返回的正文片段必须来自实际抓取页面。

### 6.2 弱命中

正文未命中或正文抓取失败，但召回阶段的标题或列表文本包含关键词。弱命中的
`hits` 使用 `title-recall` 类型，片段来自标题或列表文本，不伪装成正文片段。

仅因位于最近 30 天列表而被召回，且标题、列表和正文均未命中的页面不返回。

## 7. API 与前端兼容

保留现有 `results`、`pageUrl`、`pageTitle` 和其他已有字段。每个结果增加：

```json
{
  "matchStrength": "strong"
}
```

`matchStrength` 的取值为：

- `strong`：正文命中。
- `weak`：仅标题或列表召回命中。

统计语义：

- `totalHits` 仍只统计强命中，保持旧客户端语义。
- 新增 `weakHits`，统计弱命中结果数。
- 弱命中的 `hits[].kind` 为 `title-recall`。

`discovery` 增加以下诊断字段，字段名可按现有诊断对象命名规范调整：

```json
{
  "recentWindowDays": 30,
  "weakCandidates": 3,
  "unknownDateCandidates": 1,
  "partial": false,
  "stopReason": "date-boundary"
}
```

前端仅增加“正文命中”或“标题召回”标记，不进行页面结构改版。

## 8. FreeCMS 专用预算

该预算只在识别为 FreeCMS profile 时生效：

- 默认总时间预算为 300 秒；通用站点仍使用 120 秒。
- 初始 HTML 页面预算为 150。
- 存在高价值候选或尚未覆盖完整 30 天窗口时，可扩展到 300 个 HTML 页面。
- `searchAll.do` 和 `selectInfoMore.do` 使用独立 Provider 请求配额，不计入
  HTML 页面数，但仍受总时间预算约束。
- 达到任一预算后停止新增工作，返回已有结果，并设置
  `discovery.partial: true`。
- `stopReason` 区分日期边界、时间预算、HTML 页面预算、Provider 页数上限和
  通道失败。

## 9. 失败降级

1. `selectInfoMore.do` 失败时，继续使用 `searchAll.do`、现有栏目发现和 BFS。
2. `searchAll.do` 失败时，继续使用近 30 天列表并通过正文匹配产生强命中。
3. 单个正文页面抓取失败时，标题包含关键词的候选可作为弱命中返回；否则丢弃。
4. 会话预热失败时记录警告并继续尝试接口；连续业务失败后将该通道标记为失败。
5. 单个通道失败不能覆盖其他通道已经产生的候选和结果。
6. 诊断信息不得包含 Cookie、认证头、API Key 或完整异常栈。

## 10. 测试

### 10.1 单元测试

- 30 天截止日包含与过期日期排除。
- 时间倒序列表的提前停止。
- 日期乱序时不错误提前停止。
- 无日期结果受页数上限控制。
- 双通道 URL 规范化、合并和去重。
- 强命中、弱命中和无命中的判定。
- 强弱结果及日期排序。
- `totalHits` 与 `weakHits` 的统计语义。
- Provider 配额、HTML 页面预算和总时间预算停止。

### 10.2 Provider 与适配器测试

- 会话预热后请求 FreeCMS 接口。
- `selectInfoMore.do` 的站点、栏目、公告类型和分页参数。
- 响应中的日期、标题、URL 及 `pageurl` 大小写兼容解析。
- `searchAll.do` 失败、列表接口失败及两者分别降级。
- 单篇正文失败时的弱命中降级。
- 关联内容主机仍受 FreeCMS 域名策略约束。

测试使用本地、脱敏 fixture 和 mock，不依赖线上站点实时可用性。

### 10.3 手动冒烟测试

使用中央政府采购网最近 30 天内的普通业务关键词验证：

- 两个通道均能产生候选。
- 正文独有关键词产生强命中。
- 标题召回但正文未命中的结果标为弱命中。
- 列表翻页到 30 天边界后停止。
- 结果包含通道、预算和停止原因诊断。

线上数据会变化，冒烟测试不作为持续集成硬性断言。

## 11. 完成标准

- FreeCMS 最近 30 天采购公告同时使用关键词搜索和公告列表召回。
- 已知过期候选不会进入近期结果。
- 正文命中与标题召回在 API 和前端上可以明确区分。
- `totalHits` 的原有强命中语义保持不变。
- 任何一个 FreeCMS 通道失败时仍能获得其他通道的结果。
- 达到预算时返回部分结果和明确停止原因。
- 通用站、云南 CMS 和现有正文匹配行为不受影响。
- 新增测试覆盖日期边界、双通道、强弱命中、预算和降级路径。
