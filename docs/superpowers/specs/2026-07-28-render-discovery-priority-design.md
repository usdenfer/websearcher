# 渲染栏目发现优先级设计

## 背景

从 `https://dct.yn.gov.cn/` 单独搜索“王丹莉”时，目标文章
`/html/20203/1815552813.shtml` 未进入抓取结果。直接以文章 URL 搜索时，
现有匹配器可以正确命中正文，因此问题位于页面发现阶段。

目标站的站内搜索接口只索引标题。“王润梅”出现在文章标题中，能够借助
站内搜索补充通道找到该文章；“王丹莉”只出现在正文中，站内搜索接口返回
零结果。自动渲染虽然能从首页获得 130 个同站链接，但当前实现按 URL
字典序排列并只保留前 60 个。“通知公告”栏目入口位于第 97 位，在抓取前
就被截断，栏目翻页逻辑无法运行。

## 目标

- 从站点首页搜索正文关键词“王丹莉”时，深度 1、2、3 都能发现并匹配目标
  文章。
- 栏目和列表入口不再因首页文章链接过多而被抓取预算挤出。
- 栏目发现补充通道不受普通 BFS 深度限制。
- 保持现有总页数、并发和超时边界，避免无界扫描目标站。
- 不改变静态站点及普通 BFS 的既有行为。

## 非目标

- 不建立完整、持久化的全站正文索引。
- 不保证在单次搜索内扫描目标站的全部历史文章。
- 不改变官网站内搜索接口的能力或返回结果。
- 不扩大 `RENDER_MAX_PAGES` 和整体渲染超时。

## 方案

采用“栏目发现补充通道”：

1. 增加一个纯函数，对渲染得到的同站链接分类并稳定排序。
2. `/index.shtml`、`/index.html`、目录根路径及明显的列表入口归为发现
   入口，优先于日期型文章链接和其他页面。
3. 渲染搜索开始后，从首页链接中选取有限数量的发现入口进行渲染。该步骤
   始终执行，不取决于用户选择的深度。
4. 发现入口的分页由现有 `renderer.render_page` 收集；其中产生的文章链接
   进入补充正文抓取队列。
5. 补充正文页面与普通 BFS 页面按标准化 URL 去重，并共享现有 60 页总预算。
6. 补充阶段结束后，普通 BFS 使用剩余预算继续执行。

这一设计把“发现站点内容入口”与“用户选择的普通搜索深度”分开。深度仍
控制常规链接下钻范围，但不会关闭用于找回动态栏目旧文的补充能力。

## 链接优先级

优先级从高到低：

1. 栏目或列表入口：路径以 `/` 结束，或文件名为 `index.shtml`、
   `index.html`、`index.htm`。
2. 其他非文章型 HTML 页面。
3. 日期目录下的文章型页面，例如 `/html/2607/23_44143.shtml`、
   `/html/20203/1815552813.shtml`。
4. 其余链接。

相同优先级内保持输入顺序，以免重新引入依赖字典序的偶然行为。所有链接在
分类前执行现有的同站、协议、二进制资源和 URL 标准化过滤。

## 预算与失败处理

- 栏目发现入口使用固定的小额页面配额，避免首页栏目数量挤占全部预算。
- 补充正文页和普通 BFS 共同受 `RENDER_MAX_PAGES=60` 限制。
- 栏目渲染或正文抓取失败时，沿用 `pagesFailed` 收集错误；其他候选继续。
- 若没有识别到栏目入口，直接退回现有普通 BFS 行为。
- 自动模式只有在补充结果确实增加命中数时才采用渲染结果，保持当前降级
  语义。

## 测试

按 TDD 增加以下回归覆盖：

1. 构造超过 60 个首页链接，栏目入口位于第 97 位；断言优先排序后栏目入口
   进入发现配额。
2. 构造动态栏目分页返回深层文章链接，文章正文包含目标关键词；分别以
   depth 1、2、3 调用渲染抓取，断言目标正文页面均被抓取。
3. 断言补充页面与普通 BFS 页面按标准化 URL 去重。
4. 断言总页面数不超过现有上限。
5. 运行渲染相关测试，再运行完整 `pytest tests/ -q`。

## 验收标准

- 回归夹具中，深度 1、2、3 均能命中只存在于深层文章正文中的关键词。
- 真实目标站以首页为起点、默认自动模式搜索“王丹莉”能够返回
  `/html/20203/1815552813.shtml`。
- 全部现有测试及新增测试通过。
- 工作区不包含 API Key、临时抓取文件或调试输出。
