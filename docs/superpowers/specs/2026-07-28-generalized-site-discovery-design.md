# 泛用化站点正文关键词发现设计

日期：2026-07-28

## 1. 目标

将现有面向少数政府 CMS 的站内关键词补充能力，改造成“通用自动识别 +
可选站点适配器”的候选页面发现系统。

系统接收任意公开网站 URL 和任意关键词，根据网站结构发现候选页面，抓取
候选页面正文，并以正文可见文本的实际匹配结果作为最终命中依据。

首批重点验证：

- `https://www.gamersky.com/`（仅作为通用能力实验站，不建立专用适配器）
- `https://www.zycg.gov.cn/`
- 现有云南政府站场景

“王丹莉”只是一项历史问题的示例词，不构成业务规则。实现和测试不得包含
任何针对该词或其他具体业务关键词的特殊逻辑。

## 2. 范围和约束

### 2.1 范围内

- 自动识别搜索表单、搜索结果、分页、sitemap、RSS/Atom 和栏目入口。
- 允许适配器补充复杂网站的站点家族、搜索协议和结果解析规则。
- 支持受控的同主域内容子域发现。
- 抓取正文后匹配任意关键词，包括只出现在正文、不出现在标题中的关键词。
- 搜索通道失败时自动降级。
- 默认最多抓取 60 页；存在高价值候选时自适应扩展到 120 页。
- 单次搜索总预算不超过 120 秒。

### 2.2 范围外

- 扫描大型网站的全部历史页面。
- 建设长期、全量、持久化的站点索引。
- 绕过验证码、登录墙、付费墙或访问控制。
- 为每个新网站编写完整专用爬虫。

“任意深度”表示高价值候选不受首页 BFS 点击层级限制；它不表示在 120 秒、
120 页预算内保证覆盖大型网站的全部历史正文。

## 3. 总体架构

搜索流程：

1. 根据起始 URL 建立站点范围和请求预算。
2. 自动识别网站能力，并选择可用适配器。
3. 并行运行网站搜索、sitemap、Feed、栏目分页和普通 BFS 等发现通道。
4. 合并、归一化、去重并排序候选 URL。
5. 按预算抓取候选正文；动态入口使用 Playwright，正文优先静态抓取。
6. 对页面正文可见文本执行真实关键词匹配。
7. 返回命中结果及发现过程诊断信息。

主要组件：

### 3.1 `DiscoveryProvider`

统一的候选发现接口。每个 Provider 只返回带来源信息的候选 URL，不直接
产生最终关键词命中。

首批 Provider：

- `SearchFormProvider`
- `SitemapProvider`
- `FeedProvider`
- `CategoryPaginationProvider`
- `BfsProvider`
- `AdapterProvider`

### 3.2 `SiteProfile`

保存本次任务的站点范围：

- 注册主域。
- 允许的内容子域。
- 排除的广告、商城、登录和推广子域。
- 已识别的 CMS 或适配器。
- 可用的搜索入口与动态渲染要求。

### 3.3 `Candidate`

候选链接至少包含：

- `url`
- `source`
- `keyword`
- `title_hint`
- `score`
- `requires_render`
- `section`

### 3.4 `CandidateRanker`

根据来源可靠度、标题提示、正文 URL 特征、内容子域、栏目相关性和重复风险
进行排序。按关键词、栏目和来源设置配额，避免单一热门栏目耗尽全部预算。

### 3.5 `PageFetcher`

统一处理静态 HTTP、Playwright、并发、重试、内容类型校验和失败记录。
Playwright 主要用于发现动态链接；正文页面优先静态并发抓取。

### 3.6 `BudgetManager`

统一管理时间、页面数、渲染页数和每主机并发。所有 Provider 和正文抓取
共享预算，不能各自突破上限。

## 4. 自动探测

自动探测顺序如下：

1. 解析首页搜索表单、搜索按钮和相关 JavaScript 跳转。
2. 识别 `q`、`s`、`keyword`、`key`、`searchContent` 等常见查询参数。
3. 探测 `sitemap.xml`、sitemap 索引及页面声明的 Feed。
4. 识别搜索结果列表、正文链接和分页参数。
5. 根据链接密度、日期列表和栏目词识别内容中心。
6. 在其他通道不足时使用普通 BFS。

搜索接口返回 HTTP 200 但业务码失败、数据结构异常或内容不可解析时，视为
该 Provider 失败，而不是“没有结果”。

## 5. 站点家族

默认只允许起始主机。只有通用证据或适配器明确允许时，才扩展到同一注册
主域的内容子域。

站点家族规则：

- 内容子域可作为候选来源和正文来源。
- 广告、商城、登录、用户中心和推广域默认排除。
- 通用搜索入口来自首页可信声明时，可将同一注册主域的搜索域加入范围。
- 搜索结果返回同注册主域的新内容子域时，使用通用域名规则动态纳入；不得
  通过具体实验站域名或子域名单实现。
- 外部域名即使出现在搜索结果中也不进入抓取队列。
- 每个主机并发限制为 3 至 4，全局并发上限为 8。

## 6. 站点适配器

适配器接口：

```python
class SiteAdapter:
    def matches(self, homepage: str, url: str) -> bool: ...
    def domain_policy(self, url: str) -> DomainPolicy: ...
    async def discover(self, context: DiscoveryContext) -> list[Candidate]: ...
```

适配器通过注册表加载。域名或 CMS 判断不得散落在通用爬虫中。

### 6.1 中央政府采购网

- 识别 FreeCMS 搜索页和 `searchAll.do` 接口。
- 严格验证接口业务码和结果结构。
- 接口失败时继续搜索采购公告、信息公开、法规制度等高价值栏目及分页。
- 保留内容 ID、页码等语义查询参数。
- 动态列表使用 Playwright 发现链接，正文优先静态抓取。

### 6.2 云南政府站兼容

现有 `searchClassCount.aspx` 和 `searchN.aspx` 能力迁移为一个 CMS 适配器，
不再作为 `sitesearch.py` 的唯一固定实现。

## 7. URL 归一化

- 删除 fragment。
- 统一 scheme 和主机大小写。
- 删除已知广告追踪参数。
- 保留 `id`、`page`、`p`、`currPage` 等可能影响正文或分页的参数。
- 对查询参数排序，以便稳定去重。
- 支持页面 `canonical`，但只有 canonical 仍在允许站点家族内时才采用。
- 二进制资源、脚本、样式和媒体文件不进入正文队列。

## 8. 候选排序

优先级由高到低：

1. 网站搜索结果且标题提示命中。
2. sitemap、Feed 或栏目列表中标题提示命中。
3. 来自高价值内容栏目的正文形态 URL。
4. 其他尚未验证的内容页候选。
5. 聚合、标签、登录、重复参数或低价值导航页面。

每个关键词、来源和栏目设置候选配额。排序只决定抓取顺序；标题、URL 和
摘要均不能代替正文匹配。

## 9. 自适应预算

### 9.1 入口探测

- 目标时间：10 至 15 秒。
- 并行探测搜索、适配器、sitemap、Feed 和栏目入口。

### 9.2 基础搜索

- 首轮总页面请求预算为 60。
- 起始页、搜索/栏目列表页、渲染页和候选正文页均计入该预算。
- 使用静态并发抓取为主。

### 9.3 扩展搜索

只有存在未处理的高价值搜索结果、深分页或有效栏目入口时，才将总页面请求
预算扩展到 120。API、sitemap 和 Feed 等非 HTML 发现请求另设小额 Provider
配额，不能无限请求。

达到 120 秒或 120 页时立即停止，返回已有结果并标记 `partial: true`。

关键词引导产生的候选不受 `depth` 限制；`depth` 只控制普通 BFS Provider。

## 10. 正文匹配

最终命中必须来自抓取页面的正文可见文本：

- 去除脚本、样式、隐藏元素和明显模板噪声。
- 优先识别 `article`、`main` 或高文本密度正文容器。
- 无法可靠定位正文容器时，降级为页面可见文本，同时抑制导航和页脚重复项。
- 页面标题只用于结果展示和候选排序；关键词必须出现在目标页面正文可见文本
  中，标题、URL、元数据和搜索结果摘要均不能单独产生正文命中。
- 返回片段必须取自实际抓取的目标页面。

## 11. 错误处理

- 起始 URL 失败：返回明确的 502。
- 单个 Provider 失败：记录 warning，继续其他 Provider。
- 单个正文页失败：记录失败原因，继续剩余候选。
- 传输错误和 5xx：指数退避。
- 4xx、非 HTML 或明确拒绝：不盲目重试。
- 验证码、登录墙和访问限制：记录为受限来源，不尝试绕过。
- 达到预算：返回部分结果，不将整个任务判为失败。

## 12. API 兼容和诊断

保留现有响应字段，增加：

```json
{
  "discovery": {
    "profile": "generic",
    "sourcesTried": ["site-search", "sitemap", "category", "bfs"],
    "sourcesSucceeded": ["site-search", "category"],
    "candidatesFound": 246,
    "candidatesFetched": 103,
    "renderedPages": 4,
    "budgetExpanded": true,
    "partial": false,
    "elapsedMs": 78120,
    "warnings": []
  }
}
```

诊断信息不能包含 API Key、Cookie、认证头或完整异常栈。

## 13. 测试与验收

### 13.1 通用单元测试

- 搜索表单和 JavaScript 搜索入口探测。
- sitemap、Feed 和分页解析。
- 站点家族及排除子域。
- URL 参数归一化。
- 候选评分、分组配额和预算扩展。
- 正文容器提取与模板噪声抑制。

### 13.2 适配器契约测试

使用本地保存且脱敏的通用门户、FreeCMS 和云南 CMS HTML/JSON fixture。
持续集成测试不依赖目标网站实时可用性。

### 13.3 集成测试

构建包含以下情况的本地测试站：

- 跨内容子域候选。
- 搜索接口业务失败。
- 深分页正文。
- 关键词只在正文出现，不在标题、URL、导航或搜索结果标题出现。
- 某个 Provider 失败，但其他 Provider 仍返回正确结果。

测试关键词使用随机正文标记，不使用真实姓名或固定业务词。

### 13.4 线上冒烟测试

- 通用门户实验：以 Gamersky 验证搜索表单、分页和同注册主域内容子域能由
  通用规则发现，并确认没有加载任何 Gamersky 专用适配器。
- 中央政府采购网：验证接口失败时自动降级，搜索任务仍能返回诊断和已有结果。
- 云南政府站：使用任意正文独有关键词验证深度 1、2、3 均不阻断结构化发现。

线上内容易变化，冒烟测试手动执行，不作为持续集成的硬性断言。

### 13.5 完成标准

- 任意关键词均走相同发现和正文匹配流程。
- 代码中不存在具体业务关键词特例。
- 关键词引导发现不受 BFS 深度限制。
- 所有最终命中均可追溯到已抓取目标页面的正文片段。
- 任一发现通道失败不影响其他通道已有结果。
- 单次任务不超过 120 秒和 120 个 HTML 页面请求；非 HTML 发现请求受各
  Provider 的独立小额配额限制。
- 原有测试全部通过，新增测试覆盖通用能力和两个首批适配器。
